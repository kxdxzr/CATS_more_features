# CATS More Features v3.2.2-beta.1

**Experimental beta / pre-release. This build is still under active testing and may contain many bugs.
It is not a stable release.** Scheduled start has been tested in game, but full routes, different refuelling
modes, power saving, cooldown transitions, and real completion actions still need broader in-game verification.

## Download and run

- Download `CATS-More-Features-v3.2.2-beta.1-windows-x64.zip` from the release assets below.
- Extract the complete ZIP to a writable folder and launch **`CATS-new.exe`**.
- Read `START_HERE.txt`, configure your journal directory and route, and check the refuelling options.
- Requires **64-bit Windows** and **.NET Framework 4.7.2 or newer**. No separate Python installation is needed.
- The ZIP contains the GUI, bundled Python backend, required DLLs, input sequences, clean default settings,
  documentation, build information and checksums. The initial route is empty and completion defaults to keeping everything open.

## Changes from upstream

- Scheduled start with calendar/time selectors and `Now`, `+10 min` and `+1 hour` shortcuts.
- Completion choices: keep open, close the game and CATS, or shut down the computer with a 30-second countdown.
- Recovery of pending jumps and cooldown state from recent journal files before navigation.
- Resume-position synchronization, journal rotation/partial-record handling, and bounded navigation retries.
- Personal carrier cargo-transfer sequence adjustment and tritium-slot validation improvements.
- Build support without a private OAuth source file; a registered Frontier client ID is still required for API login.
- English README, build/deployment guide, automated checks and a clean portable beta package.

## Important behaviour and known limitations

- **Stop stops automation, not a carrier jump already submitted in the game.**
- This fork's switch to a onefile backend introduced a Stop regression that could leave the Python child process
  running. This beta includes a fix for that regression; it is not an upstream defect or a new feature, and
  stopping/restarting still needs broader in-game testing.
- Cooldown is conservatively five minutes after a recovered arrival event; missing arrival history can cause an initial five-minute wait.
- `Close game and CATS` first requests normal game exit and can terminate the game after 15 seconds if needed.
- `Shut down computer` uses `shutdown /s /t 30`; cancel the Windows countdown with `shutdown /a`.
- Automated tests do not guarantee reliable unattended operation. Game updates, menu state, display settings,
  key bindings and refuelling mode can still cause failures or regressions.
- This build does not contain a Frontier API client ID. Configure your own ID if you use the admin interface's API login.

## Verification

- Eight unit tests cover journal recovery, event matching, cancellation, held-key release and mocked completion actions.
- Windows integration checks exercise synthetic parent/child process Stop and immediate restart, GUI selectors/settings,
  and cancellation of the real onefile backend during scheduled-start and cooldown waits.
- The packaged default configuration is checked for an empty initial route, empty webhook and disabled automatic completion actions.
- Real game exit and real Windows shutdown are not triggered by these automated checks.

Please report reproducible problems at https://github.com/kxdxzr/CATS_more_features/issues with steps,
relevant configuration and log excerpts. Thanks to the original CATS project and its authors.
